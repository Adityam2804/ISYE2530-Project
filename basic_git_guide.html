Basic Git Guide

What is Git?

Git is a version-control tool used to keep track of changes made to project files. It also allows you to download a project from GitHub and upload your updated work back to the repository.

This guide uses a simple single-branch workflow:

Clone → Edit Files → Add → Commit → Push

1. Install Git

Windows:

  1. Go to git-scm.com/download/win.
  2. Download and run the Git installer.
  3. For a basic installation, the default installer options are usually sufficient.
  4. After installation, open Command Prompt, PowerShell, or Git Bash.

macOS:

Open Terminal and type: 

git --version

If Git is not installed, macOS may prompt you to install the required developer tools.

Verify that Git is installed:

git --version

You should see a Git version number.

2. Clone the Project

You only need to clone the repository the first time you work on the project. Cloning downloads the project from GitHub to your computer.

For the ISYE 2530 project:

git clone https://github.com/Adityam2804/ISYE2530-Project

Then move into the downloaded project folder:

cd ISYE2530-Project

3. Get the Latest Version

Before beginning new work, get the latest version of the project from GitHub: 

git pull

4. Edit Your Project Files

Open the project in your preferred editor, such as VS Code, and complete the assigned work.

5. Check What Changed

Use the following command to see which files you changed: 

git status

6. Add Your Changes

Add all changed files:

git add .

Or add one specific file:

git add filename.py

7. Commit Your Changes

A commit saves a snapshot of your changes. Use a short message explaining what you completed. 

git commit -m "Complete Milestone 1 tasks"

8. Push Your Changes

Push your committed changes to GitHub: 

git push
Typical workflow after the project has already been cloned: 
git pull

# Edit your project files

git status
git add .
git commit -m "Describe your changes"
git push

Important Notes

  • Work only on the assigned/default branch.
  • Do not create additional branches unless instructed.
  • Run git pull before starting new work.
  • Use clear commit messages.
  • Push your work after completing a meaningful set of changes.
